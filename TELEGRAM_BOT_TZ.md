# Техническое задание: Telegram-бот поиска музыки

## Назначение

Приватный Telegram-бот принимает от владельца обычный текст с названием
композиции, именем исполнителя или их сочетанием и возвращает готовый MP3-файл.
Реализация: Python 3.13, aiogram 3.x, SQLite, yt-dlp и ffmpeg.

Бот предназначен для записей, которые владельцу разрешено скачивать и пересылать.

## Вход и доступ

1. Основной вход — любое непустое текстовое сообщение длиной до 200 символов.
2. Команды `/start` и `/help` выводят краткую инструкцию.
3. Бот обрабатывает сообщения только пользователя с числовым ID из `ADMIN_ID`.
   Сообщения остальных пользователей игнорируются без ответа.
4. Токен Telegram, `ADMIN_ID`, токен и User-Agent VK хранятся только в `.env`.

## Алгоритм запроса

1. Запрос нормализуется: Unicode NFKC, нижний регистр и схлопывание пробелов.
2. SQLite проверяется по нормализованному ключу.
3. Если найден `file_id`, бот сразу вызывает Telegram `sendAudio` с этим ID.
4. Если `file_id` устарел, запись удаляется и запускается обычный поиск.
5. Источники проверяются последовательно:
   - VK через VKpyMusic, если задан `VK_TOKEN`; принимается только точное
     совпадение `название` или `исполнитель + название`;
   - YouTube через поисковый extractor yt-dlp;
   - SoundCloud через поисковый extractor yt-dlp.
6. Ошибка одного провайдера не завершает запрос: бот автоматически пробует
   следующий.
7. Если все источники исчерпаны, владелец получает короткое сообщение об ошибке.

Порядок можно изменить переменной `MUSIC_SEARCH_PROVIDERS`, например
`vk,youtube,soundcloud`.

## Подготовка MP3

1. VK-файл скачивается напрямую. Если контейнер не MP3, ffmpeg конвертирует его.
2. Для YouTube и SoundCloud yt-dlp выбирает лучшую доступную аудиодорожку, а
   ffmpeg удаляет видеоряд и кодирует MP3 с целевым битрейтом 320 кбит/с.
3. Имя файла формируется как `Исполнитель - Название.mp3`; недопустимые символы
   файловой системы заменяются, длина ограничивается.
4. Прямые HTTP-адреса VK и каждый редирект проверяются: локальные, приватные и
   служебные IP-адреса запрещены.
5. Размер и длительность ограничиваются переменными окружения. Временные файлы
   удаляются после отправки.

## Кэш

SQLite-таблица `track_cache` хранит исходный и нормализованный запрос, Telegram
`file_id`/`file_unique_id`, исполнителя, название, источник и даты создания и
обновления. После успешного `sendAudio` запись добавляется или обновляется. В
Docker база размещена в volume `telegram_bot_data`.

## Конфигурация

| Переменная | Обязательность | Назначение |
|---|---:|---|
| `TELEGRAM_BOT_TOKEN` | да | токен от BotFather |
| `ADMIN_ID` | да | единственный разрешённый Telegram user ID |
| `VK_TOKEN` | нет | включает поиск VKpyMusic |
| `VK_USER_AGENT` | нет | User-Agent VK-клиента |
| `BOT_DATABASE_PATH` | нет | путь к SQLite |
| `MUSIC_SEARCH_PROVIDERS` | нет | порядок провайдеров |
| `TELEGRAM_MAX_AUDIO_MB` | нет | максимальный размер, по умолчанию 49 МБ |
| `MUSIC_MAX_DURATION_SECONDS` | нет | максимум 1200 секунд |
| `TELEGRAM_MAX_CONCURRENT_DOWNLOADS` | нет | параллельные задачи, по умолчанию 1 |

## Критерии приёмки

1. Сообщение `Исполнитель - Название` запускает поиск без команды.
2. При ошибке VK автоматически используется следующий источник.
3. Итог отправляется как Telegram-аудио с расширением `.mp3`.
4. Повтор того же запроса с другим регистром или лишними пробелами использует
   сохранённый `file_id` и не вызывает downloader.
5. Пользователь с ID, отличным от `ADMIN_ID`, не получает ответа.
6. После перезапуска контейнера кэш остаётся доступен.
